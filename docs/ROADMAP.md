# Rove 如晤：从首版原型到真实设备的路线

版本：0.1；文档日期：2026-10-20。

## 1. 本轮任务的起点与范围

母任务是：“把 `Angelina-G/rove-site` 克隆到自己的 GitHub，然后开始开发产品。”

起点为提交 `d0b026570fdaefb73a339d27bf2455073fb93c5a`，包含 4 个 HTML、59 个 PDF 和 1 张 PNG。它已经描述了“主场 AR、来访 VR、共同活动与可选触觉”的产品方向，但没有实时应用服务、设备适配或可测量的双人技术链路。

本轮选择先实现**邀请进入同一空间 → 双人头手状态同步 → 共同观看 → 单次触碰请求与回应 → 退出和停止**。麦克风、摄像头由用户另外开启。房间、化身与默认触觉均标注来源，避免把样例空间和视觉提示写成扫描、真人重建或物理触感。

此范围让后续头显、腕带和网络实验能够接到同一个应用上。它不代表完整 AR 产品已经完成，也不预设 Rove 的临场感、长期使用价值或研究新颖性已经得到证明。

## 2. 首版交付与验收口径

| 本轮产物 | 验收要求 | 不能据此推导的结论 |
|---|---|---|
| 双人房间服务 | 独立客户端可加入同一房间；第三人被拒绝；房间之间隔离 | 已有生产级账号体系或大规模服务能力 |
| 三维共享视图 | 远端人物由真实收到的位姿包驱动，断线／失去追踪时降级 | 已扫描房间或追踪真实全身动作 |
| 音视频模块 | 权限显式开启；能处理双端协商；退出和停止关闭本地设备 | 已验证所有浏览器、真实摄像头与公网穿透 |
| 共享观看 | 两边使用同一 24 秒测试片，播放／暂停／拖动状态一致 | 已解决商业影视平台、DRM、长片缓冲 |
| 逐次触碰协议 | 无双边请求许可或无接收方单次接受时不得产生执行事件 | 视觉回应等于真实身体接触 |
| 停止和清理 | 停止后旧请求失效；恢复后不恢复旧触碰授权；离开时清理设备 | 已达到实体力反馈设备的停止性能 |
| 诊断和文档 | 能解释测量值来源、模拟部分与未测试条件 | RTT 就是动作／触觉端到端延迟 |

可重复的软件检查入口为 `npm run typecheck`、`npm test`、`npm run build`。服务端测试使用实际 HTTP/WebSocket 连接；浏览器联调和硬件实验仍需独立记录。**本路线说明验收目标，不替代具体测试报告。**

## 3. 阶段安排

阶段按依赖和证据推进，不承诺固定天数。当前阶段通过后再扩展，不把未接入的设备写进已交付清单。

### 阶段 A：固定首版软件基线

完成双浏览器完整用户旅程：创建、预览、拒绝、接受、动作同步、共同播放、逐次触碰接受／拒绝、停止、离开、重新加入。测试中应包含双方同时开媒体、只开一端媒体、拒绝权限、视频切换语音和暂停后重开。

需要留存：代码提交、依赖锁文件、启动参数、浏览器版本、自动化结果，以及每种测试使用的真实／虚拟设备来源。

**阶段门：** 两个独立客户端能够完成上述流程；断连、过期、拒绝、停止和换人不会让旧触碰请求或旧设备采集重新生效。没有设备时必须明确返回未支持或视觉模式。

### 阶段 B：接入一组实体头显和真实房间

先选一套实际可用的头显和浏览器／SDK，记录设备、系统版本、可导出数据及权限。取得一个主场的静态地面、墙面或简化 mesh，定义尺度、原点、朝向、共享座位和本地活动范围。再让来访端以该几何为共同坐标背景。

现有 WebXR 入口是适配起点，不是扫描完成的证据。如果设备的扫描、持久锚或场景理解能力需要原生应用，则新增明确的设备适配层；协议保留统一米制位姿，不把某厂商原始坐标直接散布到应用业务里。

需要测量：两端相同参考点的位置误差、转头后漂移、坐姿到站姿的变化、追踪丢失与恢复、实际边界内外的行为。保留标定和失败样例。开始时以坐姿任务为主，来访者不依据远端房间画面在本地盲走。

**阶段门：** 双方明确知道“主场是谁、对方在哪里”；在预先定义的受控空间内连续体验 20 分钟，记录所有跟踪中断、误定位和退出。具体误差容许值应按任务和设备先冻结，再测量，不能测试后挑选。

### 阶段 C：TURN 与两个独立网络联调

该阶段可与阶段 B 并行。部署 HTTPS 和 WebSocket 服务，配置受限 TURN 凭据，使用两个真实独立网络测试媒体。测试至少区分直连和中继，记录 ICE 选中链路、浏览器、网络、断线和重连行为。用户许可、设备关闭与房间状态仍由各端确认。

需要测量：连接成功率、建连时间、媒体丢包／抖动、语音连续性、共享播放偏差、带宽与服务资源。添加可控的延迟、丢包和带宽限制，观察触碰取消、姿态淡出与媒体恢复；网络扰动值和样本次数先写入实验方案。

**阶段门：** 双向音频和头手同步在两个网络中可重复完成；报告失败比例及中继条件。仅在一台机器或同一局域网通过，不算跨网阶段完成。

### 阶段 D：腕带驱动与真实触觉回执

先做一个可测量的低强度振动单元，明确执行器、驱动电路、通信方式、电源和停止方式。复用 `TouchEvent` 的意图层，另外定义设备命令和回执；区分“应用接受”“驱动接收”“输出开始”“输出结束”和“传感器测到”。

以台架先验证强度限幅、命令过期、持续时间、重复命令、断连停止、硬件停止。用实际传感器或同步测量装置观测执行器响应，不用客户端 Promise 成功推断物理致动已经完成。

需要测量：请求到设备接收、设备接收到输出、端到端响应分布、停止响应时间、丢失和重复输出。所有结果带设备、网络、计时方法和样本数。触碰事件的时间戳和采样时钟需要扩展，当前服务端 RTT 不够。

**阶段门：** 台架可重复验证输出与停止；两端硬件结果可关联到唯一事件；取消、超时、断连后没有旧命令延迟执行。满足本阶段条件后，再规划受控的佩戴实验。

### 阶段 E：验证“在一起”的价值

把首个任务固定为共同观看、转头说话和指向同一内容。根据实际硬件条件设计普通视频、共享空间以及主场 AR／来访 VR 的比较，不把所有高复杂度功能一次塞进实验。

关注共同注意、空间关系理解、交流顺畅程度和临场感，同时记录负担、眩晕、误触、退出与设备维护成本。先导实验用于发现流程问题和估计变异；正式样本量和指标依据研究问题确定。涉及真人参与时，由负责机构确认适用流程。

**阶段门：** 有可重复的体验收益且代价可接受，才继续投入更自然化身、长期陪伴和轻量硬件。无收益也应保留结果并调整任务，不以画面更漂亮代替价值证据。

## 4. 推迟到主链路稳定后的支线

| 支线 | 启动前提 |
|---|---|
| 真人外形与全身动作 | 头手与坐标稳定；有清楚的采集许可和对照任务 |
| A′/B′ 主场交换 | 分离参与者身份、主场提供者与会话发起者；重新确认场景和锚点 |
| 空间音频 | 普通语音可靠；有统一头部朝向和声源位置；可测听觉定位效果 |
| 气动压力、温感、面部触觉 | 振动设备链路已经实测；每种执行器单独定义反馈、限制与停止 |
| EMG／EEG | 明确它能解决现有头手输入无法解决的问题，有可比较基线 |
| 梦境、前庭刺激、实物遥操作 | 独立研究项目和独立验证，不占首版共在产品的默认范围 |

旧 PiEEG 报告中的“80–150 ms”“明确空白”等表述属于原研究材料，不能作为本原型的测量结果或新颖性证据。工程和论文引用均应回到原始出处核验。

## 5. 建议的协作方式

以下是团队建议，**不表示本次已经邀请协作者、配置 GitHub 权限或分配真实成员职责**。

- 保留上游来源和冻结提交，新增实现放在 `server/`、`shared/`、`web/`、`tests/`、`docs/`。
- 每个改动围绕一条可复现用户行为，例如“来访者拒绝请求后不输出”或“头显追踪失效后清除触碰”。PR 说明问题、变化、验证条件和未验证设备。
- 修改消息类型时同步维护校验器、双方客户端和 [PROTOCOL.md](PROTOCOL.md)。修改设备语义时同时检查默认关闭、撤回和退出路径。
- 建议按房间／协议、空间／设备、媒体／网络、研究／体验拆分责任；由团队根据实际人员确认负责人。
- 每轮演示使用明确的提交版本。演示前列出这次输入来自桌面、头显还是传感器，输出是视觉、手柄还是腕带，避免把不同证据混为一谈。

## 6. 下一轮最有用的决策输入

团队后续需要确认实际可用的两端头显、开发平台、房间采集方式、两端网络，以及拟用腕带硬件。这些选择影响阶段 B–D 的适配，不影响当前桌面链路继续开发。硬件定下来前，先保留清楚的适配边界，不提前把未经选择的设备写成既定方案。
