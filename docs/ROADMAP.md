# Rove 后续开发路线

版本：v0.2；日期：2026-10-20。

## 已推进到哪里

v0.1 建立双人房间、动作消息、样片时钟、可选通话和逐次触碰协议。v0.2 已接入用户提供的 GLB / 实测尺寸空间、双方主场切换、手动尺度与朝向确认、空间内 2D 视频人物、独立屏幕共享与 HRTF 路由。

这些不是完整的空间远程临场系统：自动扫描、自然立体人体、持久锚点、环境遮挡、真实场景碰撞、生产部署与腕带仍需开发。当前软件证据见 [VALIDATION.md](VALIDATION.md)，实际双端验收步骤见 [ACCEPTANCE.md](ACCEPTANCE.md)。

## 1. 下一迭代：完成真实的双端主旅程

以“B 的已知尺度房间 → A 接受 → 双方真人视频 → 分享一段自己的内容 → 停止并重开”为固定任务，在两个实际浏览器上执行。优先修权限、视频播放、位置确认、同屏可见性和结束分享的摩擦。

完成标准：两端都能持续看到真实收到的人物和用户选择的动态内容；没有使用内置样例替代自带房间；双方设备停止后指示灯/捕获提示结束；迟到授权不重开。记录浏览器和网络，不把协议测试当成画面验收。

## 2. 部署与跨网络媒体

部署运行 Node/WebSocket 的可达 HTTPS 服务，配置受限 TURN 凭据，并用两个独立网络验证。随后补部署运维所需的限额、监控、错误采样与版本记录。

需要记录连接成功率、建连时间、选中直连或中继、音视频丢包/抖动/带宽、用户停止响应。现阶段无账号、持久房间、横向多实例和商用服务承诺；这些能力应根据实际使用规模逐项引入。

## 3. 真实空间采集与头显

选择团队实际拥有的设备和可导出格式，接一条“采集 → 简化 → 单位核验 → 导入”的工作流。根据真实模型发现的兼容问题，决定是否支持经过独立验证的 glTF 扩展与压缩；不一次放开所有资源类型。

先用当前手动入口对齐测参考点误差与漂移，再决定持久锚点、设备场景理解或原生 SDK 的接入。测量至少包含三点定位、头手一致变换、参考空间 reset、失去追踪与恢复。几何外包范围不等于物理可行走边界。

## 4. 人物与声音的自然程度

先改善现有视频人物的位置、大小、背景处理和双方相互注视的体验。普通视频画面与全身/立体重建属于不同输入成本，按实际体验收益决定升级。

HRTF 当前是可用接口与路由逻辑，需用实际耳机和用户确认方向、距离与听觉舒适度。之后再考虑房间混响、多人声源或更自然的身体动作；不要用 UI 显示“已连接”替代感知验证。

## 5. 可测量的触觉设备

从一个振动单元开始，把现有触碰事件接到明确的设备驱动。区分应用接受、驱动接收、实际输出开始/结束与传感器测量，保留唯一事件标识。台架先测输出限幅、超时、重复、断连停止和急停，再做受控佩戴实验。

当前 Gamepad Promise 完成不是身体感觉或腕带传感器回执。压力、温感、面部触觉需要各自的执行器限制与验证，不能继承视觉模拟的验收结论。

## 6. 持久空间与产品化

在双端旅程可靠后，再增加可复用的空间库、明确的保存/删除机制、邀请管理、用户身份、诊断上报和多实例协调。是否保存空间或媒体必须有明确产品行为；当前会话模型只暂存在内存，退出后清理。

## 验收原则

每次改动对应一条可以复现的用户行为，协议、校验、双方客户端和文档一起更新。软件测试、真实浏览器、跨网络、实体头显与触觉硬件分别记录。演示固定代码 SHA，并说明房间、人物、输入与输出的来源。

原研究资料中的 EEG、EMG、梦境、前庭刺激与实物遥操作保留为独立远期方向。它们不阻塞当前空间相会主旅程，也不能用原报告的估算性能充当本实现测量值。
