# v0.2 双端体验验收

这是一份**待执行的实测规程**，不是已通过的设备报告。已经执行的软件检查列在 [VALIDATION.md](VALIDATION.md)。

## 准备与记录

运行同一个可达 Node 服务，使用两个浏览器端。桌面姿态在失焦后暂停，位置和触碰任务优先用两台保持前台的设备。媒体捕获使用 HTTPS 或 localhost；跨网络试验记录 TURN 是否配置、实际选中的 ICE 链路。头显另列型号、系统、浏览器与输入来源。

为本次记录代码提交 SHA、服务启动参数、浏览器版本、设备、网络和模型来源。准备一个自己有权使用、尺寸已知且符合 GLB 限制的房间模型。可以先用合成夹具排查链路，但不得把它记为实景扫描。

## 核心旅程

| 步骤 | 操作 | 通过条件 |
|---|---|---|
| 1. 邀请 | A 创建，B 查看并接受 | 两人进入同一会话；相机、麦克风和屏幕未自动开启 |
| 2. B 提供主场 | B 导入非内置 GLB，核对单位、地面和朝向；预览后邀请 A | B 能看到真实模型；比例/文件改变后必须重新预览 |
| 3. 接受并进入 | A 接受提案；双方等加载完成后分别确认 | 两端同一模型、名称、外包范围；B 是空间主场，A 是来访者；一方未确认时不更新人物位置或启用触碰 |
| 4. 真人画面与声音 | 双方先开语音再开视频，分别在镜头前移动 | 远端 HTML 视频与空间视频人物持续更新，声音持续；只有人物代理或状态标签不算通过 |
| 5. 空间声音 | 切我的视角，戴耳机并开启空间声音；移动和转向 | 方向、距离随人物关系变化，没有双重声音；暂停追踪后保留普通语音 |
| 6. 自选内容 | B 选择实际标签页/窗口，展示持续变化的画面，再返回 Rove | A 的公共屏幕出现同一动态内容；人物视频、麦克风继续；来源有声音时内容声音可听，无音轨时状态如实说明 |
| 7. 独立控制 | A 接收分享时关闭自己的设备；B 用浏览器原生按钮结束分享 | A 相机/麦克风关闭而屏幕继续；B 结束分享后捕获释放、公共屏幕退出分享、人物通话保留；可重新选择并分享 |
| 8. 触碰选择 | 在双端有效追踪下分别允许、靠近、伸手、逐次接受/拒绝 | 只在接受后输出，拒绝/过期/分离/撤回不输出；默认视觉，手柄独立记录 |
| 9. 停止与恢复 | 分享期间立即停止，随后解除暂停 | 本地设备与捕获指示结束；对端暂停；恢复不自动开设备、分享或触碰许可 |
| 10. 退出与换人 | B 提供主场后退出，再邀请新 B；最后 A 退出 | B 的模型不可再读取，A 回到新版本示例空间；新成员不承接旧许可；A 退出结束房间 |

提案拒绝与一分钟过期需要单独执行一次，检查当前空间没有被切换。上传时修改参数、离开时仍开着浏览器设备选择器、停止后允许一个迟到权限请求，也分别执行一次；采集不得重新开启。

## XR 补充旅程

1. 主场用 AR，来访用 VR，或先用两端 VR 排查坐标。记录实际使用组合。
2. 新空间加载后按约定入口和前方手动对齐。DOM Overlay 不可用时，用扳机/捏合完成对齐，再确认进入。
3. 选三个已知参考点，分别记录两端位置差、朝向差和地面差。站起、坐下、转头和重新定位后重复。不要先写准确度结论。
4. 让一只手暂时失去追踪，检查人物降级、触碰取消；重新获取后不得重放旧触碰。
5. 触发设备重定位/参考空间 reset，检查旧对齐失效，需要重新对齐。
6. 在进入头显授权过程中停止或退出；迟到会话应被结束。

当前未做家具碰撞或真实场景边界识别，验收先使用坐姿或受控的小范围任务。

## 留存证据

两端分别保存包含自己的模型、对方实时视频人物、动态公共屏幕的截图；截图只证明所拍时刻，不能单独证明媒体持续更新。记录一段人工观察结果，明确输入是真人、设备还是合成信号。

两端间隔数秒各导出两次诊断，核对 camera 音频与 screen 视频收发字节增长、pose 计数、空间 revision 与来源。`avatarPreference` 是显示偏好，`remoteCameraTrackLive` 和 `remoteVideoPlaying` 是轨道/元素状态，都不替代眼睛看到的画面与耳朵听到的声音。

同机、局域网、两个独立网络、实体头显分别给结果。未执行的项目记录“未测试”，不从单元测试或本机通过推断公网和硬件通过。
