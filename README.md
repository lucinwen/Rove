# Rove 如晤 · 共同在场

**带入自己的房间，邀请想见的人，在同一个空间里说话、看内容、靠近。**

> 🌐 **GitHub Pages 在线访问（研究站）：https://lucinwen.github.io/Rove/**
> 体系交互与研究路线总览、PiEEG 2026 可行性分析、触觉与多感官传递补充报告、参考文献列表均可在链接中直接查看，无需拉取仓库。空间共处原型仍需本地运行 Node 服务（见下方「快速运行」）。

当前为 **v0.2 空间共处开发原型**。这一版把 v0.1 的联网基础推进到可操作的空间流程：

**接受邀请 → 选择谁的房间 → 预览并同意空间 → 双方确认位置 → 空间内视频人物与语音 → 分享自己的窗口 → 可选触碰回应 → 停止与退出。**

源码和开发历史维护在独立仓库 [venividici/Rove](https://github.com/venividici/Rove)。浏览器实际画面、跨网络媒体和头显验收的完成情况，以 [验证记录](docs/VALIDATION.md) 为准。

## v0.2 增加了什么

| 用户可以做的事 | 实现方式 |
|---|---|
| 带入自己的房间 | 输入实测宽、深、高建立简化空间，或上传兼容的静态 GLB 房间模型；对方下载并加载同一份模型 |
| 到 A 的房间，也到 B 的房间 | 双方均可提供主场；发出提案后由另一方接受。空间提供者与会话创建者分开管理 |
| 确认大小、地面和朝向 | GLB 原始单位检查、显式米制比例、旋转、中心与地面对齐；本地预览后才能发出提案 |
| 看见对方在空间里 | 真实远端摄像头画面作为 2D 视频人物，跟随远端位置；保留简化化身模式 |
| 以自己的位置观看 | 全景观察与第一人称视角；桌面使用键鼠，WebXR 使用设备头部与双手位姿 |
| 听见声音来自对方的位置 | 用户明确开启后，以远端麦克风作为 HRTF 声源；没有有效位置时恢复普通语音 |
| 一起看自己选择的内容 | 分享标签页、窗口或屏幕；与摄像头/麦克风使用独立 WebRTC 连接，同时传输；内容音频取决于浏览器与来源 |
| 在头显里手动对齐 | 以实际 local-floor 头部位置与朝向对齐共享入口；AR 保留现实背景，VR 显示共享几何；参考空间重置后要求重新对齐 |

房间模型需要由用户事先采集或建模。v0.2 **没有自动扫描房间、重建立体真人、识别家具碰撞或驱动触觉腕带**。视频人物是一块随人定位的真实视频画面，不是全身动作捕捉或体积视频。

## 快速运行

需要 Node.js **22.12 或更高版本**。依赖由 `package-lock.json` 固定。

```bash
git clone https://github.com/venividici/Rove.git
cd Rove
npm ci
npm run dev
```

浏览器打开 `http://127.0.0.1:5173`。使用尺寸空间、共享位置和测试片不需要模型服务 API Key、数据库或头显。

构建后的运行入口：

```bash
npm run build
npm start
```

`npm start` 同时提供页面、房间 WebSocket 和模型接口。GitHub Pages 可以展示保留的研究站；新应用需要运行 Node 服务，不能只部署静态 HTML。

## 用两端完成一次相会

1. **建立会话。** A 输入昵称并创建双人房间，将邀请链接交给 B。B 查看并接受邀请。麦克风、摄像头和屏幕捕获默认关闭。
2. **准备主场。** 任一方展开“准备我的空间”，输入房间实测尺寸，或选择自己的 GLB 文件。先预览，核对单位、地面、前方与模型外包范围，再勾选确认并邀请对方切换。对方尚未加入时，可以先在本地预览。
3. **同意并进入。** 对方接受空间提案后，两端分别加载相同配置；新坐标版本清除旧位置和触碰许可。双方各自点击“确认空间并进入”后同步位置。初始示例客厅可直接体验。
4. **看见、听见彼此。** 点击“仅语音”或“开音视频”。选择“真人视频画面（2D）”时，收到的摄像头画面会出现在对方的位置。选择“我的视角”后，使用 `W/A/S/D` 移动、`Q/E` 转身、拖动转头。全景观察模式的拖动仅移动观察镜头。
5. **一起看自己的内容。** 点击“分享窗口或屏幕”，由浏览器选择器决定分享范围；如果需要内容声音，在支持的来源上开启共享音频。选完后返回 Rove。人物音视频继续，公共屏幕显示共享内容。若自动播放被浏览器拦截，点击“播放共享画面与声音”。
6. **体验空间声音。** 戴耳机，开启“声音跟随对方的位置”，用自己的视角观察与转身。HRTF 使用人物坐标；全景观察镜头不是收听者的位置。位置失效或音频图无法工作时回到普通语音。
7. **选择触碰回应。** 双方先允许请求，再靠近并伸手。接收者逐次接受，默认出现视觉回应；可另外选择支持振动的游戏手柄。没有腕带输出。
8. **停止或离开。** “立即停止”在本机立即停止位置、播放与设备，并同步暂停会话。恢复不重新开启采集或触碰许可。结束分享保留人物通话；关闭本机设备保留对方正在分享的屏幕。会话创建者离开会结束整场相会。

桌面窗口失焦或切到后台会暂停位置追踪。可以用同机两窗口测试会话和媒体；双人位置、触碰与空间声音的完整体验应使用两个保持前台的设备。完整手工验收步骤见 [双端验收](docs/ACCEPTANCE.md)。

### 准备兼容的 GLB

本版支持受限的静态 **glTF 2.0 / GLB**：单文件不超过 **20 MiB**，几何与 PNG/JPEG 贴图全部内嵌。暂不支持外部 URI、动画、骨骼、稀疏 accessor、Draco、Meshopt、KTX2 或其他 glTF 扩展；导出时使用标准三角网格与基础 PBR 材质。完整限制见 [协议文档](docs/PROTOCOL.md)。

模型导入不会猜测单位：例如原文件单位为厘米，将“每个模型单位对应多少米”设为 `0.01`。宽深支持 1–20 米，高支持 1.5–5 米。显示的尺寸是模型包围盒在所选比例和方向下的外包范围，不保证是可行走的净空。请根据自己的房间核对。

每人每次会话最多暂存 3 份模型；文件仅留在服务端内存，同房间成员通过当前连接凭据读取，提供者或房间退出后清除。当前没有持久化空间库，重启服务后需要重新上传。

### WebXR

先加载本次主场，再选择 AR 或 VR。进入后站在双方约定的对应入口，面向房间前方，点击“按当前站位对齐”，然后确认空间。没有 DOM Overlay 的头显会显示空间内提示：第一次扳机/捏合对齐，第二次确认进入；确认未得到回应时可再次操作。

这是基于真实设备位姿的手动刚体对齐。尚未实测实体头显、持续锚点、两房间的自动配准、环境遮挡或真实碰撞。当前完整姿态要求头部与双手均可追踪。

## 两台设备与部署

两端必须访问同一 Node 服务。默认监听 `127.0.0.1:5173`；需要其他设备访问时配置可达地址与 `HOST=0.0.0.0`。邀请沿用当前页面地址，其他设备不能使用发起者的 `127.0.0.1` 链接。

媒体捕获、屏幕共享和 WebXR 使用浏览器提供的安全上下文能力；公网部署使用 HTTPS，并由反向代理转发 WebSocket Upgrade。跨网络连接可能需要自己的 TURN 服务。配置入口见 [.env.example](.env.example)，环境文件不会自动加载：

```bash
node --env-file=.env --import tsx server/index.ts --production
```

仓库也提供 [Dockerfile](Dockerfile)：

```bash
docker build -t rove-prototype .
docker run --rm -p 8080:8080 rove-prototype
```

本次未构建 Docker 镜像，也未完成公网 TURN 或实体设备验收。运行和部署证据集中在 [验证记录](docs/VALIDATION.md)。

## 自动检查与诊断

```bash
npm run check
```

该命令执行类型检查、所有测试与生产构建。测试包含真实 HTTP/WebSocket、真实 Three.js GLB 解析、坐标数学、实际界面控制器以及以设备 API 替身验证的生命周期。它们不替代真实浏览器的画面与音频检查。[GitHub Actions](https://github.com/venividici/Rove/actions/workflows/check.yml) 会对提交执行同一检查。

“连接与实验记录”导出 v2 诊断 JSON：房间来源与坐标版本、人物显示偏好、实际摄像头轨道/播放状态、服务往返时延、姿态计数、样片时钟偏差、相机音频与屏幕视频收发字节、事件。导出不包含音视频、模型、邀请码、上传凭据或姿态坐标。

服务端往返时延不等于动作到画面或触觉输出的端到端延迟。媒体字节增长只能说明数据传输，画面、声音与设备效果要在两端实际观察。
